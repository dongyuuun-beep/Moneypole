# 사용자 동선, 상품 확장, 광고 위치

## 무엇을 먼저 보게 할 것인가

홈은 상품 수보다 **사용자가 맡길 금액·기간, 실제 적용 조건, 공식 원문**이 중심입니다. 헤더의 `금리 비교`는 비교 탭으로, `금리 가이드`는 하단의 짧은 해설로 이동합니다. 흰색 바탕과 회색 경계, 진한 글자로 금리·조건의 대비를 만들며 녹색 테마는 제거했습니다.

- 비교 조건 → 상품 금리와 적용 한도 → 상세 조건/계산 → 공식 안내 순서.
- 금리, 기본/최고 구분, 적용 금액을 우선 표시하고 수집 시각은 보조 정보로 표시.
- 최초 상품은 10개, 더보기로 10개씩 추가. 전체 결과 수는 그대로 표시하고 전체 목록에서 먼저 정렬한 뒤 나눠 보여줌.
- 검색 결과가 적거나 CMA처럼 데이터가 적은 화면에서는 목록 중간의 도움말/미래 광고 영역을 만들지 않음.
- 상세 dialog는 금융조건·계산·원문 확인에 집중하며 광고 위치로 사용하지 않음.

## 금융 상품을 늘린다면

아래는 **서비스 확장 우선순위에 관한 제안**이며 실제 상품 가입 추천이나 현재 구현된 수집 범위가 아닙니다. 새로운 상품 탭과 가상의 금리 데이터는 만들지 않았습니다.

| 우선순위 | 상품/비교 주제 | 머니폴과의 연결 | 반드시 비교할 정보 | 데이터 검토 |
|---|---|---|---|---|
| 1 | 수시·약정 RP / 발행어음 | CMA에서 조금 더 오래 맡기는 자금 비교로 자연스럽게 확장 | 개인/법인, 신규/기존, 기간, 중도환매율, 한도 소진, 발행사 신용위험, 예금자보호 여부 | 증권사 공식 상품 안내·수익률 공지. CMA 자동투자 금리와 직접 매수 상품 금리를 구분해야 함 |
| 2 | 개인투자용 국채 | 예금보다 긴 만기 자금의 비교 | 표면·가산금리, 만기 보유 수익률, 신청/발행일, 중도환매 시 혜택 변경 | 정부 국채 안내와 월별 발행 공고. 매일 수집보다 발행 공고 변경 감시가 적합 |
| 3 | 외화예금 | 원화 금리 비교 다음의 확장 후보 | 통화·기간별 금리, 환전 비용, 환율에 따른 원화 손익 | 은행 공식 외화예금 공시부터 검증. 원화 예금과 금리 하나로 순위를 섞지 않음 |
| 별도 화면 | ISA / 연금저축 / IRP | 절세와 장기 자금 콘텐츠로 확장 | 계좌 유형, 계좌/운용 수수료, 투자 가능 상품, 가입·인출·세제 조건 | 계좌 자체의 단일 금리는 없음. 상품 금리순 탭 대신 수수료/조건 비교를 설계 |
| 후순위 | 단기채·금리형 ETF / MMF | 단기자금 운용의 선택지 확장 | 총비용, 과거 수익률 기준기간, 매매/환매 일정, 원금 손실·가격변동 | 거래소·운용사 공시의 이용 조건과 수집 가능성을 검증한 뒤 별도 투자상품 화면으로 운영 |

처음부터 보험·대출·주식·코인까지 모두 넣기보다 `여유자금·목돈을 어디에 보관할지 비교`에 집중하는 편이 일관성이 있습니다. 대출은 개인별 적용금리·한도·상환방식에 따라 결과가 달라져 별도 설계가 필요합니다.

## 광고를 위한 자리 선점

지금 광고 스크립트·게시자 ID·광고 요청은 **없습니다**. 광고처럼 보이는 빈 배너 대신 비교에 유용한 도움말이 같은 자리를 차지합니다. 이 도움말은 실제 편집 콘텐츠이며 광고로 위장하지 않습니다. 실제 광고로 전환하면 도움말은 제거하고 `광고` 표시와 광고 전용 호스트가 보입니다.

| 슬롯 ID | 위치 | 지금 | 나중의 레이아웃 계획 |
|---|---|---|---|
| `comparison-rail` | 1200px 초과 PC 화면의 오른쪽 도움말 열 | 금리 비교 체크리스트 | 폭 300px, 전체 최소 높이 280px, 광고 본체 250px 높이 기준으로 검토 |
| `comparison-inline` | 비교 목록 첫 6개 다음, 최초 10개 이상 결과가 있을 때 | 적용 금액에 관한 비교 팁 | PC·모바일 공통, 전체 최소 높이 280px, 가용 너비와 높이가 맞는 수동 디스플레이 광고 검토 |

배치 결정:

- 첫 화면 최상단, 금액 입력/정렬/탭 바로 옆, 상품명 버튼 안, 계산 결과 바로 옆은 광고 자리에 쓰지 않습니다.
- 목록 광고는 상품 카드와 다른 영역으로 분리하고 위아래 여백을 둡니다. 광고를 순위에 포함하거나 추천 상품처럼 표시하지 않습니다.
- 오른쪽 영역은 비고정입니다. 모바일에서 별도 사이드 광고를 띄우거나 화면에 겹치는 고정 광고는 구현하지 않았습니다.
- 도움말과 광고 모드의 최소 높이를 맞춰, 광고 전환으로 아래 상품이 갑자기 밀리는 현상을 줄입니다. 실제 단위는 이 공간에 맞는 크기로 설정해야 합니다. 더 큰 반응형 광고를 허용한다면 예약 높이와 모바일 레이아웃도 함께 검증해야 합니다.
- 비교 목록 재렌더링은 광고 호스트 노드를 재생성하지 않습니다. 필터·검색·금액 입력마다 광고 요청을 반복하는 이벤트는 없습니다.

### 실제 연결 단계

`web/placements.mjs`의 `activatePlacement(slot)`은 편집 콘텐츠를 숨기고, 광고 라벨과 비어 있는 호스트를 **광고 요청 전에** 보이게 하는 준비 함수입니다. SDK나 실제 게재는 구현하지 않았습니다.

AdSense 승인·실제 단위 ID가 준비되면 별도 통합에서 다음을 처리합니다.

1. 실제 운영 주소로 사이트 심사를 진행하고, 서비스 소개·개인정보 처리 안내·문의 경로·데이터 출처와 갱신 방법을 실제 운영 내용에 맞춰 제공합니다. 승인 여부는 Google 심사에 따릅니다.
2. 광고/쿠키 사용에 맞게 개인정보 안내와 필요한 동의 흐름을 적용합니다. 현재는 광고 쿠키를 생성하지 않습니다.
3. 수동 광고 단위로 시작하여 입력/상세 화면에 원하지 않는 자동 광고가 들어오지 않게 배치를 통제합니다. 게시자 ID나 ads.txt는 실제 계정 정보를 받기 전까지 만들어 넣지 않습니다.
4. 보이는 호스트에 한 번만 광고 요청을 연결합니다. 숨겨진 PC 슬롯이나 콘텐츠가 부족한/오류 화면에서는 요청하지 않습니다. 검색·탭 전환 후에는 콘텐츠 적합성과 슬롯 표시 상태를 실제 SDK와 함께 검증해야 합니다.
5. 광고 폭·높이, 로딩 전후 레이아웃 이동, 미게재, 검색 결과 없음, 모바일의 오클릭 가능성을 확인합니다. 자신의 실제 광고를 클릭해 테스트하지 않습니다.

광고 자리를 확보하는 것만으로 승인이나 수익이 보장되지는 않습니다. 현재의 원문 조건 설명과 계산 근거처럼 자체적으로 도움이 되는 콘텐츠를 꾸준히 보강하는 것이 좋습니다.

공식 정책·설계 참고:

- [Google AdSense 광고 게재 위치 정책](https://support.google.com/adsense/answer/1346295?hl=ko): 콘텐츠/광고를 구별하고 버튼·탐색 요소 부근의 의도하지 않은 클릭을 피하는 기준.
- [AdSense 반응형 디스플레이 광고 동작](https://support.google.com/adsense/answer/9183362?hl=en): 보이는 컨테이너 크기에 맞춘 요청이 필요함.
- [web.dev CLS 최적화](https://web.dev/articles/optimize-cls/): 광고·임베드 영역의 공간을 미리 확보하는 레이아웃 원칙.
