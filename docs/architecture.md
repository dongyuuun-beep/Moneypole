# 웹 구조 검토와 매일 갱신 설계

## 현재 규모에서 유지할 구조

기존 `index.html → data.json` 정적 배포와 GitHub Pages를 유지합니다. 수백 개 상품을 하루에 한 번 확인하는 서비스는 별도 API 서버·DB가 없어도 운영할 수 있습니다. 기존 화면은 HTML·CSS·데이터 처리·계산기를 한 파일에 담고 있었으므로 아래처럼 분리했습니다.

```text
GitHub Actions (매일 02:17 KST / 수동 실행)
  collectors.py       공식 출처별 요청·파싱·전체 페이지 검증
  update_rates.py     출처별 병합·이력·실패 보존·원자적 파일 저장
    data.json         기존 배열 형식 유지 + 출처·한도·조건·확인 시각
    update_status.json 출처별 성공/실패 및 수집 범위
GitHub Pages
  index.html          의미 있는 HTML, 조건 필터·상품 목록·상세 dialog
  web/styles.css      반응형 화면
  web/app.mjs         데이터 로드·검색·정렬·상세·출처 표시
  web/rates.mjs       기간별 금리 선택·계산·확인 지연 판단
```

프레임워크 전환은 현재 문제를 해결하는 데 필요하지 않습니다. 회원 계정·관심상품 동기화·알림·검색 유입용 상품별 페이지가 필요해지면 구조를 확장하는 편이 낫습니다.

## 실제 발견한 문제와 변경

| 기존 문제 | 변경 |
|---|---|
| 파킹 수집 실패 시 기존 파킹 데이터 소실 가능 | 출처별 병합. 실패 시 기존 값·이력·확인 시각 보존 |
| CMA 수동 값 보존만 구현 | KB증권 개인 자동투자 RP·발행어음 JSON 수집 연결 |
| 은행연합회 HTML·열 위치를 가정하고 첫 숫자를 금리로 처리 | 오류 응답을 확인한 수집기 제거, 미지원 상태 공개 |
| TLS 검증 해제 | requests 기본 인증서 검증과 제한된 재시도 |
| 금감원 응답을 상품 코드만으로 조인 | 회사 코드 + 상품 코드로 조인, 상품 ID에 종류·회사 포함 |
| 일부 페이지 실패해도 부분 결과로 덮어씀 | 출처·금융권역별 모든 페이지 완료 후 병합 |
| 같은 날 재실행 시 당일 변동 이력 사라질 수 있음 | 당일 최종 값으로 재구성, 반복 실행 이력 유지 |
| 기간 필터는 카드 금리만 바꾸고 정렬은 대표금리 사용 | 선택한 기간의 금리로 표시·정렬·계산 통일 |
| 파킹·CMA가 12개월 예금 계산으로 연결 | CMA 보관 일수 계산, 파킹은 구간 검증 전 계산 보류 |
| 화면 금리가 언제 확인됐는지 불명 | 출처·확인 시각·적용일·공시일·확인 지연 분리 |
| 외부 데이터를 innerHTML에 삽입 | DOM textContent 사용, 외부 링크 HTTP(S)만 허용 |
| 수집 실패해도 정상 실행처럼 종료 | 성공 출처 저장 후 실패 종료, Job summary·아티팩트 제공 |

## 사용자 화면의 우선순위

1. 상품 종류를 선택합니다. 예금·적금과 입출금자유상품의 조건을 구분합니다.
2. 예치 금액/월 납입액과 기간/일수를 입력합니다.
3. 카드에서 표시 금리, 기본금리, 최고금리 적용 금액, 주요 우대조건, 확인 시각을 비교합니다.
4. 상세에서 금액 구간 안내·가입 대상·재투자 주기·공식 원문을 확인합니다.
5. 계산 가능한 상품에만 예상 이자를 제공합니다. 계산 불가 상품은 순위에서 그 사실을 숨기지 않습니다.

기존 최고금리 변동 그래프는 최근 변동 기록 표로 바꿨습니다. 대표 최고금리 이력을 선택 기간의 실제 금리 이력처럼 오해하지 않도록 기준을 명시했습니다. 기간별 차트는 기간·이자 방식별 히스토리를 별도로 수집한 뒤 추가하는 것이 좋습니다. 외부 Chart.js 런타임 의존성도 제거했습니다.

## 다른 수집/운영 방식 비교

| 방식 | 장점 | 비용·한계 | 이번 선택 |
|---|---|---|---|
| 공식 화면이 호출하는 JSON | HTML보다 명확한 필드, 로그인 불필요한 공개 공시 | 계약 API가 아니므로 주소·필드가 바뀔 수 있음 | 저축은행중앙회·KB증권에 적용 |
| 공식 HTML 파싱 | JSON이 없어도 가능 | 표·행·열 의미 확인 및 변경 감지 필요 | 카카오뱅크 세이프박스의 기본금리·한도·계산식 검증에 적용 |
| Playwright 브라우저 수집 | JS 렌더링·실제 공개 검색 흐름 지원 | 실행 비용·깨짐·차단 증가, 금융사이트 접근 가능성 별도 검증 | 향후 시중은행 수집 대안. 로그인/차단 우회 없이 검증 필요 |
| 공식 설명서/PDF + 변경 감시 | 복잡한 구간·우대조건 확인에 적합 | 추출 오류 및 사람이 검증할 작업 발생 | 다음 단계의 조건 검증용 |
| 제휴·유료 데이터 API | 범위·운영 지원을 계약으로 정할 수 있음 | 공급사·재배포 권한·비용 검증 필요 | 전체 금융기관 확장 시 검토. 공급사 계약은 미확인 |
| Google Sheets/수동 관리 + 출처 변경 감시 | 초기 소수 상품을 정확하게 운영하기 쉬움 | 담당자 검토 필요, 완전 자동화 아님 | 시중은행 공백의 현실적인 보완책 |
| LLM으로 임의 검색·추출 | 조건 설명 정리에 보조 가능 | 구간·적용일·금리 혼동 가능 | 금리 자동 확정 경로로 사용하지 않음 |
| Cloud Run/서버 cron + DB | 재시도·이력·알림·규모 확장에 유리 | 별도 운영·비용·자격증명 필요 | 지금은 GitHub Actions로 충분. 엄격한 실행 시각 요구 시 전환 |

매일 이 채팅의 에이전트가 실행되는 구조가 아니라, 저장소의 워크플로우가 독립 실행됩니다. 채팅 자동화는 운영 상태 점검·예외 검토를 보조하는 용도로 사용할 수 있지만, 금리 수집 실행 경로로 추가하지 않았습니다.

## 다음에 확장할 순서

- 시중은행별 공식 상품 페이지 또는 은행연합회 정상 검색 경로를 검증해 별도 수집기를 등록합니다. 현재 은행 상품은 카카오뱅크 세이프박스만 지원합니다. 케이뱅크 플러스박스는 이 환경에서 요청 시간 초과로 연결하지 않았으며, 검색에 표시된 금리를 데이터에 대입하지 않았습니다.
- 파킹통장별 전체 잔액 적용/초과분 적용, 우대조건별 금리, 한도, 이벤트 종료일을 구조화합니다. 원문 `conditions_hash` 변경 시 검증을 무효화하는 검토 테이블을 붙인 뒤 `verified_tiers`를 승인합니다. 현재 해시는 변경 식별 근거로 저장만 하며 별도 승인 화면은 없습니다.
- CMA 증권사를 추가하고 MMF·MMW 실적수익률을 약정수익률과 분리합니다. 이번에 MMF·MMW를 고정 금리로 생성하지 않았습니다.
- 판매 종료는 수집 목록 누락만으로 결정하지 않고 공식 확인과 함께 처리합니다. 현재 누락 상품은 표시 상태를 바꾸고 보존합니다.
- 관심상품과 변경 알림이 필요해지면 DB/서버리스 함수와 발송 권한을 별도로 설계합니다.

## 검증 범위

카카오뱅크 세이프박스는 공식 HTML에서 제목별 정보를 추출하고, 단일 금리로 매일 최종 잔액을 계산한다는 문구와 증액 한도를 검증합니다. 개인별 금리쿠폰은 자동 확정할 수 없으므로 기본금리 비교 범위임을 표시하며 한도 초과 금액은 계산하지 않습니다.

단위 테스트는 출처별 장애·빈 결과·중복·페이지 누락·비정상 급변·당일 재실행·기존 ID 이전·KB 개인/법인 구분·미래 적용 금리와 금액 구간 계산을 검증합니다. 로컬 브라우저는 실제 수집 JSON으로 데스크톱/모바일, 탭 전환, 검색 결과 없음, 기간 선택, 상세 열기/ESC 닫기, CMA 일수 계산, 가로 넘침 및 JS 오류를 확인했습니다. FSS 키를 로컬로 복사하지 않고 기존 GitHub Secret을 사용하는 브랜치 워크플로우로 별도 검증합니다.
